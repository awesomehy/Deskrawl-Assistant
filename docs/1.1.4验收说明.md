# v1.1.4 验收说明

适配 Deskrawl 1.0.2，可从 [GitHub Release v1.1.4](https://github.com/awesomehy/Deskrawl-Assistant/releases/tag/v1.1.4) 下载单文件程序。以下步骤供玩家继续验收新功能。

## 多个词条组合

1. 在「装备筛选规则」中选中一件装备，编辑原有组合名称，例如「冰伤流」，保存。
2. 点击「新增组合」，命名为「暴击流」，配置独立的主词条、数量和可选副词条，保存。
3. 切换组合分别检查条件，启用两者。仅命中其中一个的装备应显示「符合规则」，详情注明命中的组合。
4. 停用其中一个并保存；它不再参与判断。删除当前组合只影响该组合。
5. 复制组合后修改条件、名称并保存，确认原组合不变。
6. 导出后重新导入，全部组合和名称保留；导入的副本仍默认停用。更新程序不会重写原有规则。

同一组合的主、副词条必须同时达标；不同组合之间不会拼接命中条件。选择哪个组合编辑不影响其他已启用组合参与判断。

## 日志

1. 连接游戏后进入「日志」。第一次背包、仓库和马车清单作为基线，已有物品不会全部被记成新增。
2. 获得新装备或让宝石已有堆叠增加，检查对应的新增数量和实际位置。关闭自动锁定、自动整理后，保持连接仍应继续观察。
3. 收取马车宝石并自动入库，依次检查「马车新增」「从马车收取」「转移物品」记录。每一步都有数量、来源和目标位置，合并堆叠显示目标数量前后变化。
4. 宝石组超过单个堆叠容量时，每个实际目标格分别记录；数量相加应等于这次搬运的数量。
5. 手动锁定、解锁、背包 / 仓库双向移动，检查逐件记录，区分手动和自动。不同位置使用从 1 开始的格号，仓库按连续格号显示。
6. 搜索物品名称或操作，切换分类，查看更早记录、返回最新；重启后仍能查看历史日志。

获取日志基于每两秒完整读取的差异，两次读取之间瞬时出现又消失的物品可能无法观测。工具确认完成的搬运在提交后即记录，不依赖后续观察，也不会再次算作新增掉落。失败记录中的「请求数量」不代表已确认成功的数量；同一操作如先成功提交、随后读取失败，成功记录仍保留。

## 已完成验证

- 206 项自动检查通过，覆盖多组合任一命中、主副条件不跨组合拼接、配置兼容、日志持久化 / 分页 / 搜索、数量守恒、堆叠拆分、搬运去重及部分失败记录。
- 浏览器界面验证新增第二个组合、命名、未保存改动保护、命中组合显示，以及日志分类、分页、搜索；检查默认 1280 × 820 与最小 980 × 680 窗体排版。
- 单文件 exe 验证独立窗体、无需外部 Python、全部 444 张图标、组合及日志重启后保留、实际游戏只读连接。
- 实际游戏关闭自动写入后的观察验证：13 秒内得到 5 次不同的完整清单，没有请求锁定或搬运。本次没有新掉落；新获取和精确数量使用模拟游戏 / 模拟内存用例验证，实际新掉落链路由玩家继续验收。

发行版规则与日志位于 `%LOCALAPPDATA%\Deskrawl装备助手\`，其中 `config\lock-rules.json` 保存规则，`data\runtime\activity.sqlite3` 保存日志。打包程序不包含个人规则、日志或背包快照。
