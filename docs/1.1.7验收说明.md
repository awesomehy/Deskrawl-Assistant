# v1.1.7 更新重启修复

本版修复单文件程序自动更新后的启动问题，保留 v1.1.6 的全部功能与 Deskrawl 1.0.2 适配。

## 修复内容

已确认从 v1.1.5 自动更新后可能出现「Failed to load Python DLL」，而直接双击下载的 v1.1.6 可以正常打开。更新辅助进程继承了旧程序的解包环境；同一路径启动新 exe 时，会错误复用旧临时目录，与旧程序退出清理发生冲突。

v1.1.7 在启动更新辅助进程及启动新版 / 恢复旧版时，清理旧的私有解包环境，并设置 `PYINSTALLER_RESET_ENVIRONMENT=1`，让程序独立解包，保留用户数据目录。此方式遵循 [PyInstaller 官方的独立重启说明](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#using-sys-executable-to-spawn-subprocesses-that-outlive-the-application-process-implementing-application-restart)。

## 旧版用户升级

1. 在旧助手保存规则和整理设置，通过右上角电源按钮退出。
2. 从 [v1.1.7 Release](https://github.com/awesomehy/Deskrawl-Assistant/releases/tag/v1.1.7) 手动下载并双击 `Deskrawl-Assistant-v1.1.7.exe`。
3. 重新连接游戏，按需开启持续监控与自动整理。

首次切换请手动启动：已发布的 v1.1.5 / v1.1.6 内置更新器无法被新下载包提前修复。新版继续使用 `%LOCALAPPDATA%\Deskrawl装备助手\`，既有规则、整理设置和日志保留；后续由 v1.1.7 发起的更新使用修复后的重启方式。

## 验证

253 项自动检查通过，包含旧解包环境清理、Windows 环境变量大小写、用户数据目录保留，以及实际传给更新辅助进程的环境验证。

真实冻结的单文件 exe 在中文和空格路径下进行隔离替换验证：旧启动方式复现失败；修复后新窗体完成启动确认；故意取消启动确认后，旧程序成功恢复并打开。三种场景均保留规则文件及原程序路径。该测试使用本地同版本替换，专门验证重启与回退，不依赖网络下载。

发行 exe 另验证独立窗体、重复启动复用服务、组合管理与导入复制、配置和日志重启保留。内置代码和资源与源码一致，包含 444 张图标；未包含个人规则、背包数据或测试夹具。
