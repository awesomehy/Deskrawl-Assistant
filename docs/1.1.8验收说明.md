# v1.1.8 游戏 1.0.2a 适配与兼容性自动检测

适配 Deskrawl 1.0.2a（Steam build 25842017），保留 v1.1.7 的全部功能与独立更新重启修复，并支持普通变化的自动检测适配。

## 适配内容

- 重建 IL2CPP 类型注册、字段名、字段 token 和类型索引，更新装备注册表、背包、仓库、马车与保存对象的验证配置；继续校验游戏程序和元数据哈希。
- 修正在线仓库扩展页的 DLC 权限对象偏移，由 408 改为 416；保留普通开放页与扩展页的独立权限判断。
- 更新 GameManager、CloudClient 的静态类型入口，以及物品搬运使用的 GC 状态和写屏障位图地址。
- 修正装备锁定对保存标记内部名称的校验：`SaveSystem.nlo` 改为 `nly`，偏移仍为 92。
- 跟随新版游戏的物品操作限制：`SaveSystem` 偏移 193 为禁止状态时，锁定、转移和马车收取均拒绝写入。
- 重新提取装备、宝石、符文图标与效果，更新游戏本地化描述。仍有 209 件装备、52 件传说装备、36 种宝石和 199 种符文；本次没有新增物品，宝石和符文效果数据没有变化。

## 核验结果

- 276 项自动测试通过，包含在线 / 离线仓库权限、操作禁用状态、锁定写入边界、搬运事务回滚，以及自动适配的资源/结构/代码变化拦截。
- 真实单文件 exe 的独立窗体、444 张内置图标、词条数值预览、实际游戏只读连接、重复启动、规则与日志持久化均通过隔离目录测试。
- 已连接实际运行的 1.0.2a：背包和仓库完整读取，在线仓库开放页及扩展页权限正常，马车列表可读取。
- 一件仓库项链已完成解锁、重新锁定、移至背包及返回原仓库格子的实际测试。锁定状态、数量、词条、等级、强化和孔位保持一致，原位置恢复，游戏继续正常运行；验证期间短暂冻结约 357 毫秒。
- 静态核对确认数值解码、百分比格式与强化数值换算的指令逻辑没有变化；主副词条池、基础属性排除规则及宝石堆叠字段仍适用。
- 实际游戏的马车当时为空；此次未用真实马车物品执行收取。相关字段、实体清理逻辑、写屏障及收取事务通过静态检查和模拟测试。

## 玩家验收

1. 退出旧助手，运行 `Deskrawl装备助手-v1.1.8.exe`，点击「连接游戏」。既有规则、整理设置和日志继续使用原来的用户目录。
2. 查看已有装备的词条数值与命中高亮；选择装备测试锁定或解锁，再验证按规则锁定和持续监控。
3. 测试背包与仓库双向移动，确认同种同等级宝石优先堆叠。
4. 马车中有物品时，启动自动整理，验证指定物品收进背包、宝石继续自动入库。

启动后持续监控和自动整理默认暂停，请按需要手动开启。

## 自动检测适配范围

连接时自动核对本地游戏程序、元数据和资源。检测到版本变化后解析 IL2CPP v39 类型与 Windows x64 代码，核验字段类型、布局、词条枚举及 16,328 项代码特征。保存字段和装备注册表混淆名称、元数据序号、角色及在线仓库入口和 GC 写屏障地址可在校验通过后自动刷新。

解析器只读取文件，不加载 GameAssembly.dll，不注入或调用游戏方法，也不通过锁定或搬运试探兼容性。代码特征保留常量、字段偏移、分支目的、调用关系、导入符号及字符串内容。资源数据有增减或变化、字段类型或布局变化、枚举变化、代码逻辑或编译结构变化，以及无法唯一定位或不支持的格式，提示「需要维护适配」并阻止操作。本版采取保守范围，资源描述或不相关代码变化也可能触发维护；新增装备、宝石、符文、图标和效果仍由人工维护内置目录。

适配数据仅用于当前连接，`data/runtime/game-compatibility.json` 是诊断记录，不授予下次连接的兼容性。连接期间游戏文件变化会停止锁定、搬运和整理，重新连接后再次检测。

文件副本验证已将 SaveSystem 保存字段 `nly` 改为 `zzz`、装备注册表类 `gj` 改为 `zz`，并将 GameManager 入口从 RVA `0x3a17cd8` 移至 `0x3bc35f0`；自动适配通过并输出正确的新字段名和地址，完整检查约 44 秒。测试未修改安装目录或游戏内存。实际游戏已完成只读连接与完整清单读取。
