# 1.4.6 验收说明

适配 Deskrawl 1.0.3 / Steam build 25973417。

## 结算识别与自动推图

- 原先只按波次结束标记、波次索引、存活怪物数和已通关记录判断完成，未使用已经读取的原生结算弹窗。辅助数据不一致时，可能一直显示进入关卡或刷图中。
- 现在结合对应的原生结算弹窗、当前关卡计划、原生结束标记和已通关记录核验完成；普通关卡与神话裂隙分别匹配各自弹窗。
- 结算核验重新读取当前计划并检查完整快照。角色、场景或计划正在变化时等待重新读取，不仅凭弹窗计数，也不把新一局尚在战斗的计划判为通关。
- 普通进图与观星切图共用进图确认规则；目的地、难度和新的计划身份均需匹配。上一局残留的结算记录不再确认同地图进图成功；新一局确已结束时仍可正常核验。
- 本局通关核验与离开许可继续分开：先收取地面奖励，再确认地面已清空且结算稳定，最后回城整理及推进，通关记录按现有机制去重。
- 结算结果尚未核验时显示明确的等待状态；场景切换诊断补充波次、怪物数、结束标记及通关依据，便于后续定位。

## 配置兼容

不新增配置项，沿用 1.4.5 的规则、关卡、托管预设、合成上限、符文跳过名单及其他本地设置。

## 验证与范围

已按本机当前游戏程序集核对原生结算弹窗和波次结束流程，未执行实机刷图或提交游戏动作。离线用例覆盖辅助数据不一致、普通／裂隙弹窗隔离、计划切换和快照变化、新旧进图确认、奖励拾取与后续推进。

1856 项 Python 测试、179 项前端测试通过；正式单文件窗体和显式测试入口通过隔离启动、配置保存重启验证。冻结程序实际读取 GitHub HTTPS 更新信息成功；原生证书组件、源码与包内容核对通过。

本次修复的是可导致同类现象的代码缺口；尚未复现报告者现场，不能断定其唯一根因或认定是 1.4.5 新引入的回归。

GitHub Release 提供 `Deskrawl-Assistant-v1.4.6.exe`。个人配置、凭证、日志和掉落留档不随程序分发。
