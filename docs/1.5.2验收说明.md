# 1.5.2 验收说明

目标：Deskrawl **1.1.0 / Steam build 26310087**，Windows x64。验证日期：2026-10-30。

## 宝箱分批整理

- 按背包中宝箱的实际总数量计算，达到 20 个时回城，不计仓库中的宝箱。
- 主城达到阈值，或背包已满且存在可开启宝箱时，优先开启本批宝箱并处理装备，再收取后续马车和地面物品；收取后再次达到阈值，继续同一流程。
- 本批开始后继续处理剩余可开启宝箱，不因数量降到 20 个以下就重新无限收取；开箱结果未回读时等待，不重复提交。
- 新装备先按规则锁定保护、分区存放或处置；锁定、身份未核验的宝箱不自动开启。药水等保留物品继续占用原背包格位。
- 保留 Boss 掉落离场前的收取核验，不因宝箱阈值直接跳过本局奖励。

## 仆从装备筛选与保护

- 使用已启用的具体装备筛选规则判断仆从装备，接入背包与仓库的命中筛选、组合详情、词条高亮、自动锁定和持续监控。
- 回城整理分别显示“符合筛选规则的角色装备”和“符合筛选规则的仆从装备”；两类均固定锁定入库，分别使用角色、仆从装备仓库页，不重复整理同一物品。
- 仆从黑雾传说固定保护；未命中普通传说和稀有独立配置入库、出售或分解。待核验或已锁定装备继续保留，命中物品不能进入托管出售或分解。
- 不增加仆从装备的角色自动换装行为；交易所上传及 Steam 出售仍使用原有独立授权与强制保留规则。

## 配置兼容

- 旧版未命中处置、仆从存放页及其他规则与托管预设继续保留；没有仆从配置时默认入库。
- 开发阶段可编辑的命中处置字段兼容读取后丢弃，命中装备统一固定保护；保存、重新启动后仍不允许出售或分解。
- 观星入口继续隐藏，旧开启状态强制关闭，历史奖励勾选保留；既有南瓜王优先、宝石和符文合成及有效 Steam 登录凭证继续沿用。

## 验证记录

- 完整回归：1949 项 Python 测试与 193 项 Node 界面测试通过，43 个文档本地链接核验通过。
- Windows x64 单文件 exe 在隔离目录、无外部 Python 的环境下完成 WebView2 窗口启动、配置保存重启及 GitHub HTTPS 更新检查；冻结界面确认命中仆从装备固定保护，退休配置字段不再保存。
- 使用真实 1.4.6、1.5.0 和 1.5.1 版本代码生成旧配置，验证迁移、保存与重新加载；三版旧更新器均能发现并核验实际 1.5.2 exe，可直接升级。
- 宝箱回归覆盖多栈计数、满包、锁定与待核验、回执延迟、新装备优先保护，以及保留药水情况下连续处理 100 个宝箱与 101 件装备的有界模拟。
- 仆从装备回归覆盖命中与未命中、固定保护、独立仓库页、自动锁定、持续监控、执行前复核及旧字段保存迁移。
- 用户已验收当前开发版功能。批量宝箱流程使用自动化模拟验证，不声称已经进行 100 个宝箱的真实游戏消耗测试。
- 发布包不包含个人配置、游戏快照、多开或远控预研模块，继续保留 HTTPS 证书校验。
