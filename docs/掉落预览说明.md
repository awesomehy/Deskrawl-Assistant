# 本趟掉落预览

## 使用

1. 启动游戏并进入在线角色，在助手顶部点击“连接游戏”。
2. 打开“掉落预览”页签，进入在线关卡。完整计划稳定后，自动列出所有波次的计划物品；保持此页签，每 2 秒更新，无需为每一关点击刷新。
3. 切换关卡会替换整份列表。回城、断开游戏或读取失败时清空列表；页面显示原因并自动等待下次读取。也可点击“重新读取”。

无需开启装备持续监控或自动整理。预览不操作游戏，不请求新的关卡或提交奖励。默认不保存计划；可以独立开启下面的高价值掉落监控。

## 显示范围

每波显示计划金币、药水充能、全部物品条目。物品显示中文名称与图标、品质、等级、部位、远古 / 黑雾、孔数和效果说明。装备使用与背包相同的分类器，分开显示基础属性、主词条、副词条，按已保存并启用的组合高亮选中词条；基础护甲、武器速度和武器伤害不参与计数。符合规则、主词条全中的标记也沿用背包规则。不能完整确认的词条留在“未确认词条”组，不计为命中。

`loot-item-ui.json` 收录当前安装资源中的全部 573 个 ItemData / GemData / RuneData：209 件装备、36 种宝石、199 种符文和 129 种其他物品，每个精确 ID 均有本地图标。仆人解锁物品按实际 SlaveToUnlock 引用对应名称，不猜测名称前缀。效果沿用游戏文本和序列化属性；没有独立特殊效果的装备显示说明，不编造效果。资源中存在不表示当前所有条目都可掉落。后续服务器新增且本地没有的 ID 仍明确显示未知，并保留原始标识。

符文等非装备的品质使用实际 ItemData.Rarity，避免空字段或通用 Common 协议字段覆盖其固定品质。显示优秀、稀有、宏伟和符文套装；颜色来自游戏 GraphicsConfig，套装绿色为 `#33ff4c`。装备继续使用本局生成品质和黑雾 / 神圣标记。

物品等级使用游戏计划及物品提示框中的原始整数，和角色等级是两个数值。例如角色等级 56 时物品等级可以是 568；本体生成物品与提示框均直接使用该整数，不除以 10。

“计划物品”按掉落条目计数，装备按件数计数。装备、宝石、符文和宝箱的一条计划对应一个生成实例；材料按游戏消费计划时的 `max(qty, 1)` 规则显示数量。未知类型的数量显示未确认。金币合计仅包含波次金币，不包含宝箱内金币。

这是服务器的**尚未结算计划**，完成波次仍不代表奖励已入库；失败、中断、服务器结算校验等情况可能改变最终获得。宝箱自身可以预览，箱内物品要到结算后确认。寻宝、采集和其他不在波次计划中的收益不在此列表内。离线模式没有此在线计划，页面会说明。

## 已核验的数据来源与适配

基于 Deskrawl **1.0.2a / Steam build 25842017** 的本地代码和运行时外部只读观察核验：在线开局响应被反序列化为 `RunPlan`，其中各 `RunWave.loot` 已包含具体 `PlanItem` 和 `PlanModifier`；在线波次完成后游戏消费此计划生成掉落，最终提交奖励另行进行。并非通过抓包解密得到物品，网络响应使用 TLS 加密。

本预览复用助手已核验的进程连接和静态词典，独立配置为 `data/loot-plan-types.json`。仅接受上述版本已核验的游戏文件散列，并验证运行时类型、完整字段布局和文件状态；未来版本即使助手其他功能完成自动适配，此预览仍需独立核验。

- global-metadata SHA-256：`57627070d0fe8a00f82e373100768f529c4829f02d6aeb8ac3057aaab13cacfc`

读取前确认在线角色处于战斗区，活动地图与波次管理器的地图、计划一致，计划模式已启用，计划地图标识与活动地图匹配。复制后重新检查所有读过的稳定字段与数组；切关、变化或完整性异常时拒绝这一份数据。回城时先排除战斗区，再访问可能残留的计划。对波次、物品、词条、字符串及数值均设置读取上限。界面仅使用连接会话与关卡标识的摘要区分场次，不暴露原始关卡标识或进程地址。

## 高价值掉落留档

在页面顶部勾选“开启监控”，连接游戏后每 2 秒独立检查，切换到其他页签仍运行，不依赖托管、自动整理或锁定。重启助手后默认关闭。页面显示保存数量、最近保存时间及实际留档目录。正常 exe 目录为 `%LOCALAPPDATA%/Deskrawl装备助手/data/runtime/loot-captures`，数据目录覆盖设置仍生效；开发版使用 `data/runtime/loot-captures`。

触发类型：神圣装备、黑雾装备、宏伟符文、符文套装，以及金条、传说缰绳、开光石等全部可交易物品，按本地游戏资源中的 Steam 物品定义识别，不依赖市场报价请求。计划中出现时保存该场次；实际观测到新增高价值 UID 时也保存，即便计划没有该物品。没有 UID 的道具使用地面／马车的稳定掉落观测标识，并记录数量；完整清单确认掉落消失后，再次出现的对象作为新事件，避免游戏复用对象地址导致漏录。首次完整物品清单作为基线，已有物品不算新增；同一物品在地面、马车间转移不重复记录，有 UID 的物品转入背包、仓库同样去重。不以背包位置变化或数量增加证明新掉落。换角色、重新连接或重新开启监控会重建基线。原始计划与实际观测分开，不写入托管累计掉落统计。

每局一个 JSON，追加本局实际观测，内容包括：首次读取时间与波次、原始 RunPlan 场次上下文、各波 WaveLoot、全部 PlanItem 原始字段（包含 dropId、baseItemId、品质、古代 / 黑雾标记、孔数、数量、金币和完整 PlanModifier），以及高价值命中与实际新增证据。这是内存中的原始掉落部分，不是网络原始报文，也不包含敌人配置。若本局计划后来变化，同时保留首次与最新版本。

同一连接中关闭后重新开启监控、再次读到已留档场次时，会恢复最早的计划与已有观测，不覆盖开局证据或重复增加文件计数。已有文件损坏时保留原文件并提示读取失败。

精确 UID / dropId 和物品 ID 相符才标记为 `exact_id`；只存在同名模板仍为 `unconfirmed`。无 UID 道具的 `observation_id` 和本地 `observation_event_id` 只用于观测去重，不能代替计划中的 dropId，不证明该物品属于开局计划。无法对应到已缓存场次时保存 `unattributed` 证据，原始计划留空，不拿其他局的数据代替。普通场次仅短暂缓存在内存，最近四局可供回城后的实际掉落对应；不会把所有普通局写入磁盘。

开局读取若已经超过第一波，文件会记录真实首次波次，不能据此声称开局时已包含该物品。两次采样间瞬时出现并消失的物品可能漏读，监控只能积累正面证据，不能凭“没记录”断言该物品不在计划中。磁盘写入失败会显示错误并重试；文件只保存在本机，不自动上传 GitHub，发布包不包含这些个人留档。

## 验证

自动测试覆盖城镇残留计划排除、离线模式、地图与计划不一致、复制期间关卡 / 数组变化、未知版本和字段布局、空物品计划、材料与装备数量、词条格式、读取失败及断连清空。`GET /api/loot-preview` 禁止附加参数；`POST /api/loot-capture` 只接收布尔开关，并验证请求来源与会话，无领奖或修改掉落操作。

前端进入页签立即读取，定时刷新；断连、错误、等待状态及过期响应不能恢复旧列表，所有动态文本进行转义。发布包必须包含独立计划类型配置，且不含个人规则、计划快照或玩家数据库。
