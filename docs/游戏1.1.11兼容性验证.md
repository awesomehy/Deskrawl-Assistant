# 游戏 1.1.11 兼容性验证

验证日期：2026-11-12。目标：Deskrawl **1.1.11 / Steam build 26604532**，Windows x64。

依据 [官方更新公告](https://steamstore-a.akamaihd.net/news/externalpost/steam_community_announcements/1849192144180924)，结合本机安装文件、元数据、原生代码及运行中游戏的只读快照适配现有功能。不增加仆从赋能或装备转化的自动操作，不改变原有配置开关。适配阶段未执行实机消耗操作；后续 v1.6.2 发布准备见 [验收说明](1.6.2验收说明.md)。

## 接口与文件核验

- 8 份类型配置、118 项类型记录的完整字段和方法信息与当前游戏文件逐项核对。
- 刷新并核对 57 个原生动作入口、6 个导出入口、单例和 5 个未初始化类型令牌；兼容基线覆盖 15903 个原生方法。
- 修正 GameManager、ItemData、Player、仆从管理器等结构的字段移动，覆盖背包、仓库、马车、关卡、掉落、统计、商人、成长、合成、拍卖行及重连使用处。

- 装备词条池继续使用游戏实际职业过滤，未因增加新装备而自行扩展词条规则。

## 验证结果

- Python **2717 项**、前端 Node **277 项**测试通过。
- 后续修复商人购买的校验容量不足，并将宝箱批次阈值改为 30 个；相关 Python **153 项**、前端 **12 项**测试通过，覆盖 60 格满包、保留药水、分批开箱及南瓜王回城判断。
- 针对性覆盖七阶合成上限与旧配置保留、新旧 DLC 独立授权、八页仓库、当前天赋方案、双 Boss 不提前计数、远古神圣独立身份与保护、魔盒提交参数和装备配方排除。

- 已使用正式运行时连接当前游戏，在独立审计目录读取数据，禁止安装动作分发器或调用游戏方法；读取完成后关闭审计连接，游戏与原助手保持运行。

### 后续商人购买停止修复

用户测试时，15:16:38 的十件戒指购买在指令编码阶段报“前置校验数据超出限制”，尚未提交该批购买。独立只读复现保留原生购买前检查，在假的分发器处截获后结束：60 格背包、30 格占用时需要 387 条八字节校验，超过原来的 384 条上限。

将校验表容量扩至 512 条，仍使用原有 16 KiB 分配，不删除物品、报价、余额、场景或在线同步校验。测试实际执行本测试进程内的指令模拟，确认最后一条校验不符时，任何游戏调用都不会执行；十条商人调用加 512 条校验可以完整编码，超限或超出分配仍拒绝。复核时商店窗口已关闭，实际购买前检查按预期拒绝继续；未重新打开商店或执行消费。
